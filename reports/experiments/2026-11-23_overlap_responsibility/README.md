# 避碰責任：重疊時兩車都負責，脫離後只剩後車

日期：2026-11-23；分支 `master`；基於 `1d4a182`，含未提交修改，接續[前車成本懲罰](../2026-11-23_responsibility_leader_penalty/README.md)。

## 使用者要求

- 使用者明確要求：把避碰邏輯改成「兩車開始重疊時，兩車都有避碰責任；第一次脫離重疊後，只剩後車有責任」。理由使用者未說明。
- 使用者在提問中選定：
  - 重疊指縱向並排重疊。
  - 依決策當下的實際狀態判定。
  - 有責任者硬剔除，沒有責任者不限制。
- 量測前，使用者的 main 為 `leader_soft=True`、兩個權重 0、守方 `collision_horizon=0.1`、`decision_period=0.1`。以此作為基準。

## 方法

[responsibility.py](../../../strategy/responsibility.py) 的 `ResponsibilityConfig` 新增 `overlap_rule`（預設 False；與 `leader_soft` 只能擇一）。依決策當下兩車碰撞框中心的縱向差 Δs₀ᶜ（對方 − 自車）與 L̄（兩車碰撞框長的平均，目前 0.6 m）逐對判定：

| 決策當下 | 自車責任 |
|---|---|
| \|Δs₀ᶜ\| < L̄（重疊中） | 有，兩車都有 |
| Δs₀ᶜ ≥ L̄（對方完全在前） | 有 |
| Δs₀ᶜ ≤ −L̄（自車完全在前，已脫離） | 沒有，只計 leader 懲罰；main 權重為 0，等於不限制 |

- 有責任：每個 k≥1 的預測點都要滿足 ‖Δc_k‖ ≥ r_col（0.6 m），違反就剔除候選。**不套 ℓ**，所以 `slope`、`offset` 在此模式不使用。
- 只看當下狀態，就能涵蓋「開始重疊 → 兩車負責 → 脫離 → 只剩後車」，不另存歷史。
- 攻守策略都已透過 `evaluate_responsibility` 取得結果，策略程式只修改了 `leader` 成本項的顯示條件。
- main 改為 `leader_soft=False`、`overlap_rule=True`，其餘使用者設定不變。

## 實驗設定

- 場景：main 預設，`rounded_rectangle`、21 s。
  - vehicle-1：`relative_overtake`，11 m/s。
  - vehicle-2：`defend`，9 m/s，起點領先 4 m。
- r_col=0.6 m，碰撞框 0.6×0.4 m。每組各跑一次（確定性模擬）。
- 命令：`measure.py <out.json> --overlap-rule [--defense-collision-horizon 1.0]`。
- [measure.py](measure.py) 另外記錄：重疊步數（|Δs| < 0.6 m），以及碰撞步數中有幾步發生在重疊中。
- [summarize.py](summarize.py) 列出主要指標。

## 結果

| 組別 | 最終 s（攻／守） | 攻方首次領先 | SAT 碰撞步數（重疊中） | 重疊步數 | no_feasible（攻／守） | 守方剔除數（首次的實際間距） |
|---|---|---|---|---|---|---|
| [基準：leader_soft、0.1 s](baseline_leader_soft.json) | 214.4／183.8 | 7.12 s | 51（50） | 78 | 12／2 | 14（攻方已領先 0.17 m） |
| [**重疊規則、0.1 s（目前 main）**](overlap_h0.1.json) | 206.9／183.5 | 10.40 s | 73（71） | 188 | 31／12 | 126（攻方落後 0.47 m） |
| [重疊規則、守方 1.0 s](overlap_h1.0.json) | 218.4／183.7 | **5.52 s** | **26（26）** | 66 | 10／4 | 50（攻方落後 0.47 m） |

- 以 main 預設值執行的 [main_final](main_final.json)，與「重疊規則、0.1 s」完全相同。
- 決策耗時：攻方 86～118 ms，守方約 45 ms。
- 三組的首次碰撞都在 4.46 s。
- 日誌與 json 同名。

**目視觀察（依日誌與剔除時間軸）**
- 兩組重疊規則中，守方第一次被限制都在 4.44 s。
  - 當時攻方落後 0.465 m，剛進入重疊；攻方在 d≈−0.40、守方在 d≈0.00，橫向只差約 0.4 m。
  - 守方 7 個候選全部被剔除，沿用前一路徑到 4.90 s。
- 守方 1.0 s 組：5.02 s 起守方改選 −0.2，避開在 +0.56 的攻方，攻方 5.52 s 領先。
- 0.1 s 組：
  - 守方全部候選被剔除 12 次，攻方 no_feasible 31 次。
  - 重疊步數 188，是基準的 2.4 倍。
  - 10.40 s 才超車。
- 守方被限制時的實際間距都在 −0.60～+0.32 m（重疊中或剛被超越）。沒有出現攻方還在遠處就被限制的情況。

**Claude 分析，未經使用者確認；待驗證**
- 重疊規則確實讓守方只在「真的重疊」後才受限，不會因預測被超越而提前讓路，與使用者的設定一致。
- 重疊一開始，兩車橫向常已小於 r_col（約 0.4 m 對 0.6 m），守方剛取得責任時就已經沒有可行路徑，只能沿用舊路徑。這可能是 4.46 s 首次碰撞的原因。
- 守方檢查時長 0.1 s 時，有責任的守方只看 0.1 s，難以規劃避開，造成兩車長時間重疊。改成 1.0 s 後碰撞較少、超車較早。由於角色已依當下狀態判定，較長時長不會再造成提前讓路，但這仍只是單一場景的結果。

## 驗證

- `MPLBACKEND=Agg python -m unittest`：401 項，3 項失敗，與先前同名（[日誌](unittest.log)）。整合測試仍是第 99 行約 0.01 的差異。
- [test_responsibility.py](../../../tests/test_responsibility.py) 共 36 項，全部通過。新增 7 項涵蓋：
  - 重疊中的前車要負責，且不被 ℓ 放寬（對照 a=40 與 leader_soft 都免責）
  - 已脫離的前車即使預測被追上也免責
  - 完全在後的車要負責
  - L̄ 使用碰撞框長並以車身中心計算
  - 非法設定
  - 攻方重疊中須避開後車、脫離後不受限
  - 守方重疊時不能切向攻方，攻方尚未重疊（落後 0.8 m 但較快）時仍可阻擋

## 限制

- 單一場景、單次執行。r_col 與守方檢查時長都未調參；main 仍是使用者設定的 0.1 s。
- 重疊只看縱向；左右已分開很遠時也算重疊，兩車都要負責。
- 距離使用圓形 r_col，與 SAT 矩形不一致。
- 對手預測仍不互動。
